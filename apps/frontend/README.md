# apps/frontend

Web client for AI Project Vault. Owns presentation-layer code only — no domain logic, no direct data-store access, no direct AI provider calls.

Talks to `apps/backend` over the documented API surface (`src/lib/api-client.ts`), and to no other service directly.

Vite + React 19 + TypeScript SPA (ADR-012 — not Next.js), Tailwind CSS v4, TanStack Router (file-based, `src/routes/`) + TanStack Query, Zustand, React Hook Form + Zod, shadcn/ui conventions (`components.json`, `src/components/ui/`).

Phase 1 shipped the application shell only (error boundary, loading screen, a health/version widget). Phase 2 added the Identity & Organization Platform: `/login` (Google Identity Services button), a protected `/dashboard`/`/profile`/`/organization` shell with RBAC-aware route guards, `/unauthorized`, a Zustand auth store (`src/stores/auth-store.ts`) with silent session recovery and automatic 401-refresh-retry (`src/lib/session.ts`, `src/lib/api-client.ts`) — see [ADR-013](../../Docs/03_ARCHITECTURE_DECISIONS.md#adr-013-phase-2-session-strategy--client-side-google-identity-services-short-lived-jwt--rotating-httponly-refresh-cookie). Phase 3 adds `/storage-connections` (list/connect/verify/disconnect Google Workspace) and `/connectors/google/callback` (completes the server-side OAuth exchange after Google's redirect) — see [ADR-014](../../Docs/03_ARCHITECTURE_DECISIONS.md#adr-014-phase-3-google-workspace-connector--server-side-authorization-code-flow-with-a-frontend-hosted-callback-encrypted-token-storage). Phase 4 adds `/scans` (current-scan progress polling, start/cancel actions, scan history, last-successful-scan) — see [`Docs/phases/PHASE_04_STORAGE_INTELLIGENCE.md`](../../Docs/phases/PHASE_04_STORAGE_INTELLIGENCE.md). Phase 5 adds `/files` (file browser) and `/files/$fileId` (metadata panel, classification, extraction status, knowledge attributes, related-files list), plus an "Enrichment" status/progress section on `/scans` — see [ADR-017](../../Docs/03_ARCHITECTURE_DECISIONS.md#adr-017-knowledge-engine-phase-5--deterministic-first-pipeline-content-extraction-and-scanenrichment-chaining). Phase 6 adds `/search` (query box, ranked results with a retrieval-method badge and score, linking into `/files/$fileId`) and `/chat` + `/chat/$conversationId` (conversation list, message thread, a per-message citation panel linking to file detail), plus an "Embedding" status/progress section on `/scans` mirroring Enrichment's — see [ADR-018](../../Docs/03_ARCHITECTURE_DECISIONS.md#adr-018-ai-intelligence-engine-phase-6--ai-gateway-abstraction-local-first-embeddings-mean-centered-similarity-and-a-stubbed-completion-provider). Phase 7 rebuilds `/dashboard` into the real Founder Command Center (organization overview stat tiles, storage health with a trend sparkline, knowledge health, an AI insights feed, a top-priority recommendation preview with a "Refresh recommendations" action, and a recent-activity feed) and adds `/recommendations` (category/status filters, search) plus `/recommendations/$recommendationId` (full detail: confidence, estimated impact, risk, suggested action, affected files, related departments) — see [ADR-019](../../Docs/03_ARCHITECTURE_DECISIONS.md#adr-019-recommendation-engine-phase-7--organization-scoped-jobs-aggregate-not-per-item-recommendations-and-a-100-deterministic-rule-set). Phase 8 adds the Execution Engine's surface: `/execution-plans` (Execution Center — status-filtered plan list) and `/execution-plans/$executionPlanId` (Plan Viewer + Risk Summary + step list + a Rollback trigger for owners/admins); `/approvals` (Approval Queue — per-row and bulk approve/reject/request-changes, with a required extra confirmation checkbox before an owner/admin can approve a high-risk plan, directly enforcing the phase spec's "impossible to accidentally approve high-risk operations"); `/execution-jobs` (Execution History with a one-click Failed Jobs filter) and `/execution-jobs/$executionJobId` (Job Progress View + Execution Timeline of per-step results + pause/resume/cancel controls); plus a "Create execution plan" action on the recommendation detail page. Every one of these pages makes clear that nothing touches Google Drive until an owner or admin explicitly approves it — see [ADR-020](../../Docs/03_ARCHITECTURE_DECISIONS.md#adr-020-execution-engine-phase-8--drive-trash-instead-of-deletion-org-scoped-plans-reusing-the-jobrollback-machinery-and-a-narrow-ruleaction-allowlist). Phase 9 adds the Automation Engine's surface: `/workflows` (Workflow Library — list/create) and `/workflows/$workflowId` (version history, a trigger form for scheduled/event/manual triggers, publish/manual-trigger/pause/disable/clone actions) plus `/workflows/$workflowId/builder` (a JSON node-graph editor — add/remove/edit nodes and their `next_nodes` wiring; a visual drag-and-drop canvas is an explicitly deferred future iteration, the backend graph format doesn't depend on it); `/workflow-executions` (Execution History with a Failed-runs filter and polling while a run is active) and `/workflow-executions/$workflowExecutionId` (per-node Execution Log plus pause/resume/cancel controls); `/workflow-policies` (Policy Manager — draft/publish/archive); `/automation-templates` (Templates Gallery, grouped by category, one-click apply into a new workflow); `/notifications` (in-app inbox); and `/automation` (Dashboard overview — active workflows, pending approvals, recent/failed runs). See [ADR-021](../../Docs/03_ARCHITECTURE_DECISIONS.md#adr-021-automation-engine-phase-9--policies-as-a-second-kind-of-approver-promoting-execution-engine-services-to-packagesshared-and-a-db-polled-scheduler). Phase 10 adds no new routes — it's a hardening pass on the backend/worker/infrastructure this app talks to. One transitive dev-only dependency vulnerability was found and fixed (`brace-expansion`, pulled in via `eslint`, patched via a `pnpm-workspace.yaml` override — never shipped in the actual built bundle regardless). Bundle size was reviewed: route-based code splitting is already automatic via TanStack Router's file-based routes, and the main vendor chunk (251.9 kB / 79.2 kB gzipped) was judged reasonable for a full-featured SPA — no changes made. See [ADR-022](../../Docs/03_ARCHITECTURE_DECISIONS.md#adr-022-production-hardening-phase-10--stub-until-configured-observability-a-db-polled-cache-instead-of-a-new-subsystem-and-an-iac-reference-implementation-validated-but-never-applied).

```bash
pnpm install
cp .env.example .env   # set VITE_GOOGLE_CLIENT_ID to test Google sign-in
pnpm dev
```
